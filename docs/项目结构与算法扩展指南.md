# Actor-Critic 项目结构与算法扩展指南（面向算法入门开发者）

> 适用人群：
> - 第一次接触强化学习工程化代码的同学
> - 想基于 A2C/QAC 快速实验并扩展为 PPO、SAC（离散版）等算法的开发者

---

## 1. 先理解这个仓库在做什么

这个项目是一个**离散动作空间**下的强化学习实验框架，当前内置两种算法：

- `A2C`（Advantage Actor-Critic）
- `QAC`（Q-based Actor-Critic）

工程目标不是“把某个算法写到极致”，而是：

1. 提供统一入口、统一训练循环；
2. 通过配置快速切算法；
3. 让新增算法的成本可控（尽量少改主流程）。

## 2. 项目目录拆解（按“你会改哪里”来理解）

```text
Actor_Critic/
├── main.py                     # 训练入口：读配置、建环境、建 agent、启动训练
├── trainer.py                  # 通用训练循环（episode/step/日志/可视化）
│
├── config/
│   └── default.yaml            # 默认配置（环境、算法、学习率、可视化等）
│
├── utils/
│   ├── config.py               # YAML + CLI 覆盖配置的解析逻辑
│   └── visualization.py        # 训练曲线绘图
│
├── env/
│   └── make_env.py             # Gymnasium 环境创建
│
├── agents/
│   ├── base_agent.py           # 算法统一抽象接口
│   ├── __init__.py             # agent 注册中心 + build_agent 工厂
│   ├── a2c_agent.py            # A2C 实现
│   └── qac_agent.py            # QAC 实现
│
├── models/
│   ├── actor.py                # 策略网络
│   └── critic.py               # V/Q 价值网络
│
└── tests/
    ├── test_agent_factory.py   # 算法工厂与注册机制测试
    └── test_visualization.py   # 可视化产物测试
```

### 2.1 数据流（非常关键）

一次训练流程可以理解为：

1. `main.py`：读取配置 + CLI 覆盖；
2. `make_env`：创建环境；
3. `build_agent`：根据 `algorithm` 构建具体 agent；
4. `Trainer.train()`：
   - 调 `agent.select_action(state)` 拿动作；
   - 与环境交互拿到 `transition`；
   - 调 `agent.update(transition)` 回传 `critic_loss/actor_loss`；
   - 记录并打印日志；
5. 训练结束后绘制曲线。

所以你可以记住一句话：

> **Trainer 不关心算法细节，算法细节都在 Agent 的 `update()` 里。**

## 3. 怎么使用这个框架（从 0 到跑通）

## 3.1 安装依赖

```bash
pip install torch gymnasium pyyaml matplotlib
```

## 3.2 用默认配置训练

```bash
python main.py
```

## 3.3 切换算法（A2C/QAC）

```bash
python main.py --algorithm qac
```

## 3.4 覆盖关键超参数

```bash
python main.py --algorithm a2c --num_episodes 300 --actor_lr 1e-4 --critic_lr 1e-4
```

## 3.5 关注输出

- 控制台日志：按 `log_interval` 输出近 N 回合平均奖励；
- 图片输出：`plot_path` 路径下保存奖励/Loss 曲线。

## 4. 你要重点理解的“可扩展机制”

为了降低新增算法的接入成本，项目做了两层约束：

1. **接口约束**：所有算法都必须继承 `BaseAgent` 并实现
   - `select_action(state, deterministic=False)`
   - `update(transition)`
2. **注册约束**：通过 `register_agent("name")` 注册进工厂，主流程无需改动。

这意味着：

- Trainer/主入口不需要知道 PPO/SAC 内部怎么优化；
- 只要新算法符合接口并注册，就能直接被 `--algorithm xxx` 调用。

## 5. 如何扩展一个新算法（模板级步骤）

下面以“新增 `ppo` 算法”为例（伪代码骨架）：

### 第 1 步：新建文件

在 `agents/` 下新建 `ppo_agent.py`。

### 第 2 步：实现接口并注册

```python
from agents.base_agent import BaseAgent
from agents import register_agent

@register_agent("ppo")
class PPOAgent(BaseAgent):
    def __init__(self, state_dim, action_dim, config):
        ...

    def select_action(self, state, deterministic=False):
        ...

    def update(self, transition):
        # 返回 (critic_loss, actor_loss)
        return critic_loss_value, actor_loss_value
```

### 第 3 步：在 `agents/__init__.py` 增加导入

```python
from agents.ppo_agent import PPOAgent
```

> 这样做的目的是让模块加载时执行装饰器注册。

### 第 4 步：配置文件中设置

```yaml
algorithm: ppo
```

### 第 5 步：运行

```bash
python main.py --algorithm ppo
```

## 6. 入门开发者最容易踩的坑

1. **`update()` 返回值不规范**
   - Trainer 期望 `(critic_loss, actor_loss)` 两个数值。
2. **action 张量类型错误**
   - 离散动作通常要 `LongTensor`。
3. **done 逻辑漏掉 truncated**
   - Gymnasium 有 `terminated` 和 `truncated` 两种结束条件。
4. **设备不一致（cpu/cuda）**
   - state、model、loss 计算都要在同一 device。
5. **注册了类但没被 import**
   - 装饰器注册依赖模块执行，没 import 就不会入表。

## 7. 当前框架的不足与建议演进方向

这个项目对教学非常友好，但如果要做更严肃实验，建议逐步增强：

1. **缺少经验回放/批量更新抽象**
   - 目前是一步一更新（on-policy 风格），对某些算法不够通用。
2. **日志系统较轻量**
   - 建议引入 TensorBoard/W&B，记录更多指标（entropy、KL、梯度范数等）。
3. **评估与训练未分离**
   - 可加 `evaluate()` 周期性无探索评估。
4. **可复现实验配置还可增强**
   - 增加运行目录、配置快照、随机种子全量设置（numpy/torch/cudnn）。
5. **缺少算法单测粒度**
   - 建议补 `update()` 数值稳定性与维度检查测试。

## 8. 快速自检清单（每次改算法前后）

- [ ] `python -m unittest discover -s tests` 通过
- [ ] `--algorithm 新算法名` 能正确创建 agent
- [ ] 奖励曲线文件能输出
- [ ] 至少跑几十回合，确认 loss 没有立即 NaN

---

## 9. 一句话总结

你可以把这个仓库当成一个“强化学习算法插槽框架”：

- `Trainer` 管流程，
- `Agent` 管算法，
- `register_agent` 管接入。

当你保持这三层边界清晰时，扩展新算法会非常顺滑。
